# Article Deposit Errors #

The purpose of this page is to help publishers understand some of Router's error messages which may occur from time to time when article packages are deposited.

| Error Text   | Explanation |
|--------|-------------|
| Failed to create notification from file - Problem with notification metadata: DataSchemaException('Cast function `coerce_to_ymd` failed - Unable to parse 0000 with any known format.')  | Indicates that a supplied date (publication date, accepted date or a history date) has value '0000' which is not recognised as a legitimate year. |
| Filename: issue-files.zip – Failed to create notification from file - Problem reading file: */Incoming/ftptmp/ 757b2058f09645b0b9a6b5ecc2460b24/ 0cb3e501553148e49a86dd0b9dbe9d12/ a60ba32c64044c35a28f3108a091ff4b.zip*. Error: No JATS metadata found in package   | This indicates that the supplied package does not contain an XML file with JATS metadata.  **However, in this particular case the error can be ignored as it is known that a zip file with a name (like) 'issues-files.zip' contains summary information about an Issue, rather than an article, so there is nothing for Router to process.** |
| Failed to create notification from file 'XXXXX' - Problem storing file: */Incoming/ftptmp/ blah999blah888blah777blah666blah/ blah555blah444blah333blah222blah/XXXXX.zip*. Error: Failed to store file 'ArticleFilesJATS.zip' in remote container 'YYYYYY'. Return code: 413. | Indicates that the supplied zip file, after repackaging by Publications Router, exceeded the maximum permitted file size of 2560MB. <br><br>This error is rare. It occurs where the supplied zip file is originally under Router's limit of 2356MB, but after repackaging by Router (which involves unzipping and re-zipping) it then exceeds the limit (because the compression level used by Router is lower than that used for the originally zip file).<br><br>Such large zip files typically contain supplementary video clips or other large media or data files.<br><br>The only solution is to reduced the size of the zip file and resubmit it. |
| The following error occurred while Publications Router was processing an article deposit with filename 'a_large_file.zip':<br><br>Error flattening FTP deposit file 'a_large_file.zip' - Zip file too large (2826938921 bytes); maximum allowed is 2469606196 bytes.   | This error occurs when the supplied zip file is larger than the maximum size 2356MB permitted before repackaging is attempted.   <br><br>The only solution is to reduced the size of the zip file and resubmit it. |
